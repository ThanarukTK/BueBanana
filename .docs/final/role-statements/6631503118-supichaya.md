## Statement (≈200 words)

I built the first version of the backend — commit `6b6922b`, "[Added] backend mvp": the package and
TypeScript setup, the Elysia app with its first routes, the domain types and initial pricing helpers, the
in-memory store, and the first tests, plus the backend documentation the rest of the team built on.

My decision was to keep the store in memory for the first cut. It let the API and the tests run with no
database, no credentials and no network, which is why the automated tests could be written from day one and
why they still run in about a second. I put the store behind an interface so the Postgres implementation could
be added later without touching the routes, which is what eventually happened.

What I would do differently: the first version authenticated staff with a single shared token. That decision
outlived the MVP — the backend still has no staff-account API, so the console verifies credentials itself, and
that is a weaker boundary than a real account table with roles. A staff-account endpoint belonged in the first
cut, not in a later sprint that never came.
