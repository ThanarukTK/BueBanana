# UAT Instruments — Consent, Scenarios, SUS & UTAUT2 (TH/EN)

Companion to `docs/test-plan.md` §4–§5. All instruments are delivered through **one Google Form**
(sections A–K); print §5 (scenario cards) and §6 (observer sheet) on paper. Every form and sheet uses
the participant code `P01…P15` only.

Instruments: SUS = Brooke, J. (1996). UTAUT2 = Venkatesh, V., Thong, J. Y. L., & Xu, X. (2012),
*MIS Quarterly* 36(1), 157–178 (items in the paper's Appendix A, adapted). The Thai wording below is a
translation prepared for this study — say so in the report, and check the English appendix against the
paper if your advisor requires verbatim items.

---

## 1. Section A — consent & briefing (read aloud, Thai)

> สวัสดีค่ะ/ครับ เรากำลังทดสอบระบบเช็กอิน–เช็กเอาต์ด้วยบัตร NFC ของร้าน ซึ่งเป็นโครงงานของนักศึกษา
> สิ่งที่เราอยากทราบคือ **ระบบใช้งานง่ายหรือไม่** ไม่ใช่ทดสอบตัวคุณ — จึงไม่มีคำตอบที่ผิด
> ระหว่างทดลองจะมีพี่คอยบันทึกเวลาและปัญหาที่พบ ไม่มีการบันทึกวิดีโอหรือเสียง
> เราเก็บข้อมูลแบบไม่ระบุตัวตน (ใช้รหัส P01–P15) และคุณสามารถหยุดได้ทุกเมื่อโดยไม่ต้องแจ้งเหตุผล
> ข้อมูลส่วนตัวจะไม่ถูกเผยแพร่ และแจ้งลบข้อมูลได้ตลอดเวลา
> แบบฟอร์มจะถามความยินยอมก่อน จึงจะเริ่มข้อถัดไปได้ครับ/ค่ะ

English appendix version:

> We are testing the café's NFC check-in/check-out system, a student project. We want to know whether
> **the system** is easy to use — this is not a test of you, so there are no wrong answers. An observer
> will time the task and note any problems; no video or audio is recorded. Data is anonymised
> (P01–P15), you may stop at any time without giving a reason, and you may ask for your data to be
> deleted. Do you consent to take part?

| Section A field | Type | Notes |
|---|---|---|
| Participant code (`P___`) | short answer, required | The note-taker writes the same code on the observer sheet |
| Consent | checkbox, **required**, single option, no preselected default | "ยินยอมเข้าร่วมการทดสอบและให้ใช้ข้อมูลตามที่แจ้งข้างต้น" |
| Age band | multiple choice: under 18 / 18–24 / 25–34 / 35–44 / 45+ | Band, not date of birth (PDPA minimisation) |
| Gender | multiple choice: ชาย / หญิง / ไม่ระบุ | UTAUT2 moderator |
| Experience | multiple choice: first time using this system / used it before | UTAUT2 moderator |
| How often they visit this café | multiple choice: first visit / 1–2 ครั้งต่อเดือน / ทุกสัปดาห์ | Context for interpretation, not analysed as a moderator |

**Do not** collect name, phone number, email, national ID, or the raw NFC UID. If an incentive needs
contact details, use a separate paper sheet that is not linked to the participant code.

## 2. Section B — SUS (Thai, 5-point)

> กรุณาระบุระดับความคิดเห็นต่อระบบที่คุณเพิ่งใช้: 1 = ไม่เห็นด้วยอย่างยิ่ง, 5 = เห็นด้วยอย่างยิ่ง

| # | ข้อความ | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 1 | ฉันคิดว่าฉันอยากใช้ระบบนี้บ่อย ๆ | ☐ | ☐ | ☐ | ☐ | ☐ |
| 2 | ฉันรู้สึกว่าระบบนี้ซับซ้อนเกินความจำเป็น | ☐ | ☐ | ☐ | ☐ | ☐ |
| 3 | ฉันคิดว่าระบบนี้ง่ายต่อการใช้งาน | ☐ | ☐ | ☐ | ☐ | ☐ |
| 4 | ฉันคิดว่าฉันต้องให้คนที่มีความรู้ทางเทคนิคช่วย จึงจะใช้ระบบนี้ได้ | ☐ | ☐ | ☐ | ☐ | ☐ |
| 5 | ฉันรู้สึกว่าฟังก์ชันต่าง ๆ ของระบบนี้ทำงานเชื่อมโยงกันอย่างดี | ☐ | ☐ | ☐ | ☐ | ☐ |
| 6 | ฉันคิดว่าในระบบนี้มีความไม่สอดคล้องกันมากเกินไป | ☐ | ☐ | ☐ | ☐ | ☐ |
| 7 | ฉันคิดว่าคนส่วนใหญ่จะเรียนรู้การใช้งานระบบนี้ได้อย่างรวดเร็ว | ☐ | ☐ | ☐ | ☐ | ☐ |
| 8 | ฉันรู้สึกว่าระบบนี้ใช้งานยุ่งยาก | ☐ | ☐ | ☐ | ☐ | ☐ |
| 9 | ฉันรู้สึกมั่นใจเมื่อได้ใช้ระบบนี้ | ☐ | ☐ | ☐ | ☐ | ☐ |
| 10 | ฉันต้องเรียนรู้อะไรหลายอย่างก่อนที่จะเริ่มใช้ระบบนี้ได้ | ☐ | ☐ | ☐ | ☐ | ☐ |

**Scoring** (not an average): items 1,3,5,7,9 → `score − 1`; items 2,4,6,8,10 → `5 − score`. Sum →
× 2.5 → 0–100. `test-session-log.csv` (column `SUS_score_calc`) computes this. Benchmark mean ≈ 68
(68–80 good, 80+ excellent, under 51 poor).

## 3. Sections C–J — UTAUT2 (Thai, 5-point)

> 1 = ไม่เห็นด้วยอย่างยิ่ง, 2 = ไม่เห็นด้วย, 3 = เฉย ๆ, 4 = เห็นด้วย, 5 = เห็นด้วยอย่างยิ่ง
> ให้คะแนนตามประสบการณ์จริงของคุณเมื่อสักครู่ ไม่มีคำตอบที่ผิด

### C. Performance expectancy (PE) — 4 ข้อ

| Code | ข้อความ |
|---|---|
| PE1 | ฉันคิดว่าระบบเช็กอิน–เช็กเอาต์นี้มีประโยชน์กับการมาใช้บริการร้าน | 
| PE2 | การใช้ระบบนี้ช่วยให้ฉันเช็กอินและเช็กเอาต์ได้เร็วขึ้น |
| PE3 | การใช้ระบบนี้ช่วยให้การเข้า–ออกจากร้านมีประสิทธิภาพมากขึ้น |
| PE4 | การใช้ระบบนี้ช่วยเพิ่มโอกาสที่ฉันจะได้สิ่งที่ต้องการจากร้าน (เช่น ได้โต๊ะเร็วขึ้น) |

### D. Effort expectancy (EE) — 4 ข้อ

| Code | ข้อความ |
|---|---|
| EE1 | การเรียนรู้วิธีใช้ระบบนี้เป็นเรื่องง่ายสำหรับฉัน |
| EE2 | การโต้ตอบกับระบบนี้ชัดเจนและเข้าใจง่าย |
| EE3 | ฉันคิดว่าระบบนี้ใช้งานง่าย |
| EE4 | ฉันสามารถใช้ระบบนี้ได้อย่างชำนาญได้ง่าย |

### E. Social influence (SI) — 3 ข้อ

| Code | ข้อความ |
|---|---|
| SI1 | คนที่สำคัญกับฉันคิดว่าฉันควรใช้ระบบนี้ |
| SI2 | คนที่มีอิทธิพลต่อพฤติกรรมของฉันคิดว่าฉันควรใช้ระบบนี้ |
| SI3 | คนที่ฉันให้ความสำคัญกับความคิดเห็น อยากให้ฉันใช้ระบบนี้ |

### F. Facilitating conditions (FC) — 4 ข้อ

| Code | ข้อความ |
|---|---|
| FC1 | ฉันมีสิ่งที่จำเป็นสำหรับการใช้ระบบนี้ (เช่น บัตร NFC) |
| FC2 | ฉันมีความรู้ที่จำเป็นสำหรับการใช้ระบบนี้ |
| FC3 | ระบบนี้เข้ากันได้กับอุปกรณ์หรือการใช้งานอื่นที่ฉันใช้ |
| FC4 | ฉันสามารถขอความช่วยเหลือจากพนักงานได้เมื่อมีปัญหาการใช้ระบบนี้ |

### G. Hedonic motivation (HM) — 3 ข้อ

| Code | ข้อความ |
|---|---|
| HM1 | การใช้ระบบนี้สนุก |
| HM2 | การใช้ระบบนี้เพลิดเพลิน |
| HM3 | การใช้ระบบนี้สร้างความบันเทิงได้ดี |

### H. Price value (PV) — 3 ข้อ

> อ้างอิงค่าบริการของร้าน คือ 30 บาทต่อชั่วโมง

| Code | ข้อความ |
|---|---|
| PV1 | ค่าบริการของร้านเมื่อเทียบกับความสะดวกที่ได้จากระบบนี้ สมเหตุสมผล |
| PV2 | ระบบนี้ให้ความคุ้มค่ากับเงินที่จ่าย |
| PV3 | ด้วยราคาปัจจุบัน ระบบนี้ให้ความคุ้มค่าที่ดี |

### I. Habit (HT) — 4 ข้อ

| Code | ข้อความ |
|---|---|
| HT1 | การใช้ระบบนี้กลายเป็นนิสัยของฉันแล้ว |
| HT2 | ฉันติดการใช้ระบบนี้ |
| HT3 | ฉันต้องใช้ระบบนี้ |
| HT4 | การใช้ระบบนี้กลายเป็นเรื่องธรรมชาติสำหรับฉัน |

> HT1–HT4 assume repeated use. For a first-time participant they will mostly score 1–2; that is not an
> error, it is what the construct asks. Say so in the report instead of dropping the construct.

### J. Behavioural intention (BI) — 3 ข้อ

| Code | ข้อความ |
|---|---|
| BI1 | ฉันตั้งใจจะใช้ระบบนี้ต่อไปในอนาคต |
| BI2 | ฉันจะพยายามใช้ระบบนี้ทุกครั้งที่มาใช้บริการร้าน |
| BI3 | ฉันวางแผนจะใช้ระบบนี้อย่างสม่ำเสมอ |

**28 items.** Construct score = mean of its items (computed in `test-session-log.csv` as `PE_mean` …
`BI_mean`). Use-behaviour is **not** asked here: M1 (task success) and M2 (time on task) are the
behavioural evidence. Report Cronbach's α per construct, and note that with n = 15 α is indicative only.

## 4. Section K — open questions (write verbatim)

1. อะไรคือสิ่งที่ทำให้คุณสับสนมากที่สุดระหว่างใช้ระบบ? (What confused you most?)
2. ถ้าต้องใช้ระบบนี้อีกครั้ง คุณอยากให้ปรับอะไร? (What would you change?)
3. ถ้าไม่มีพนักงานอยู่เลย คุณคิดว่าจะเช็กอิน–เช็กเอาต์ได้ด้วยตัวเองไหม เพราะอะไร?

## 5. Section cards — hand to the customer (Thai)

**S1 — alone (timing scenario, every participant)**
> คุณมาใช้บริการคนเดียว ใช้บัตร NFC แตะเพื่อเช็กอินที่เครื่องหน้าเคาน์เตอร์ สั่งเครื่องดื่ม เล่นเกมประมาณ
> 30 นาที แล้วบอกพนักงานว่าขอเช็กเอาต์และจ่ายเงิน
> *ก่อนพนักงานคิดเงิน ให้คุณบอกเป็นปากเปล่าว่าคุณคิดว่าต้องจ่ายเท่าไร*

**S2 — friends arriving together, then one late**
> คุณมากับเพื่อน 1 คน แตะบัตรเช็กอินพร้อมกัน ผ่านไปประมาณ 5 นาที เพื่อนอีกคนมาถึงและอยากเล่นโต๊ะเดียวกัน
> ให้เขาพยายามเช็กอินด้วยตัวเอง

**S3 — group splits**
> คุณมาเป็นกลุ่ม 4 คน อีก 20 นาทีต่อมา สองคนต้องกลับก่อนและจ่ายเงินแยก ส่วนคุณกับเพื่อนอีกคนอยู่ต่ออีก
> 20 นาทีแล้วจ่ายรวมกัน

**S4 — card problem**
> บัตรที่พนักงานให้ใช้แตะแล้วขึ้นข้อความแจ้งเตือน ให้คุณจัดการกับสถานการณ์นี้และเช็กอินให้สำเร็จด้วยตัวเอง

## 6. Observer sheet (one per session — mirrors `test-session-log.csv`)

| Field | Notes |
|---|---|
| `participant_id` | `P01…P15`, same code as in the form |
| `age_band`, `gender`, `experience_first_time_1_0` | copy from the form; 1 = first time using this system |
| `task_success_1_0` | 1 only if check-in **and** check-out completed with **no** staff rescue **and** bill matched |
| `checkin_time_s` | stopwatch: tap → confirmation on the reader / floor view |
| `checkout_time_s` | stopwatch: customer asks for the bill → amount shown and accepted |
| `staff_assists` | count every intervention; one neutral prompt after 60 s stuck counts as 1 |
| `errors_seen` | which error state appeared (unknown card, disabled, network) and who recovered |
| `bill_expected_thb` / `bill_shown_thb` | expected said out loud before staff confirm; shown = system amount |
| `TC_IDs_touched` | e.g. `TC-CI-01, TC-CI-02, TC-CO-01, TC-CO-05` |
| `notes_verbatim` | quote in the customer's own words, tagged with the participant code |

Anything that fails goes into `docs/defect-log.csv` with the matching `TC_ID` **before** the next
session starts.
